# AgentReachGuard v0.3.0

AgentReachGuard v0.3.0 moves the analyser from primarily file-level Google ADK parsing toward repository-level security reachability analysis while preserving its static-first, local-first security model.

## Highlights

- Repository-aware Google ADK analysis across Python modules.
- Cross-file resolution for tools, helper functions, delegation, identities, OAuth scopes, MCP configuration, and execution boundaries.
- Conservative static handling of simple factories, nested workflow agents, conditional tool references, and common list construction patterns.
- Static MCP endpoint constant resolution with runtime-derived endpoints retained as explicit coverage uncertainty.
- Improved ADK framework semantics for Bash confirmation and provider-managed code execution.
- Reduced false positives from generic `.execute()` methods, arbitrary URL literals, ordinary dictionary access, and framework-fixed managed-service destinations.
- Improved MCP authentication detection, including dynamic header values and `X-Goog-Api-Key`.
- Repository resolution metrics in coverage output.
- Additional correctness regressions derived from representative public ADK projects.

## Security semantics

v0.3 continues to distinguish observed static configuration, declared policy, and inferred relationships. Attack paths remain potential risk combinations with runtime exploitability marked as not verified.

Coverage diagnostics are intentionally conservative. When AgentReachGuard cannot safely resolve a runtime-generated construct, imported helper, dynamic MCP endpoint, or authentication state, it reports analysis uncertainty rather than assuming the construct is safe.

AgentReachGuard does not import or execute the target application, launch agents or MCP servers, or query live cloud control planes during a normal static scan.

## Validation

The release candidate has been validated with:

- 228 automated tests.
- 26/26 reviewed benchmark cases passing.
- Precision 1.000 and recall 1.000 on the reviewed fixture corpus, with zero benchmark false positives and false negatives.
- Ruff checks passing.
- GitHub Actions CI passing on Python 3.11 and 3.12.
- CodeQL passing.
- Wheel build/install and secure-fixture smoke testing in CI.

The benchmark metrics describe the reviewed fixture corpus; they are not a claim of universal real-world detection accuracy.

## Compatibility

There are no intended breaking changes to the documented CLI or manifest schema. Existing `scan`, `rules`, `baseline`, JSON, SARIF, strict-mode, suppression, and repository-configuration workflows remain supported.

## Known boundaries

v0.3 does not prove runtime exploitability or complete live cloud authority. Arbitrary dynamic Python, third-party helper semantics, live IAM inheritance, runtime control effectiveness, and non-Python ADK SDKs remain outside complete static coverage.

Future work is tracked in `ROADMAP.md`.
