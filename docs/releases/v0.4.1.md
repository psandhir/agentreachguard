# HorusTrace v0.4.1

HorusTrace v0.4.1 is a hardening release focused on improving real-world static
analysis coverage across LangGraph, MCP, OpenAI Agents SDK, Google ADK, and
notebook-heavy agent repositories.

## Highlights

### Broader LangGraph normalization

- Detects function-local and class-bound `StateGraph` construction.
- Recognizes factory-created agents such as `create_react_agent`.
- Resolves more finite conditional-routing patterns, including symbolic
  `START` / `END`, list path maps, and `tools_condition`.
- Recognizes `ToolNode(...)` without requiring an explicit node name.
- Gives LangGraph graph instances source-scoped identities so unrelated
  `builder` / `workflow` variables in different files are not merged.

### Programmatic MCP discovery

- Adds Python-native MCP discovery for common client and server patterns.
- Supports FastMCP, stdio, SSE, streamable HTTP, MultiServerMCPClient,
  context-managed MCP clients, and `connect_to_server(...)`.
- Improves static MCP URL, authentication-header, and Python runtime command
  resolution.
- Distinguishes external/runtime MCP configuration from statically proven
  endpoints instead of silently treating it as complete.

### OpenAI Agents SDK hardening

- Recognizes generic constructors such as `Agent[Deps](...)`.
- Improves hosted tool, delegated agent/tool, Temporal `activity_as_tool`,
  and imported tool handling.
- Avoids falsely classifying unrelated local Python packages named `agents`
  as the OpenAI Agents SDK.

### Notebook and template handling

- Statically scans Python code cells in Jupyter notebooks without executing
  notebook content.
- Ignores shell commands and non-Python cell magics during Python analysis.
- Adds a bounded notebook-specific file-size ceiling for output-heavy notebooks.
- Distinguishes Jinja/Cookiecutter templates and explicit source snippets from
  broken executable Python.

### Repository branding cleanup

- Removes remaining pre-HorusTrace project-name references from active source,
  repository templates, and contributor documentation.
- Removes pre-rebrand markdown release-note copies from the current documentation
  tree; Git tags and GitHub releases remain the historical record.

### Coverage and ADG correctness

- Coverage diagnostics now include structured details such as file, line,
  reason, framework context, and exception information.
- Adds explicit coverage diagnostics when a supported framework is detected
  but no agent can be normalized.
- Prevents same-named LangGraph graphs in separate files from cross-wiring
  tools and control-flow edges in the Agent Dependency Graph.
- Keeps unresolved runtime behavior visible as incomplete coverage rather than
  assuming it is safe.

## Real-world validation

The hardening work was exercised against a public corpus of 30 agent/framework
repositories split into:

- 21 application repositories
- 9 framework-stress repositories

The application cohort completed with:

- 21/21 repositories cloned and scanned
- 0 scanner errors
- 0 scanner timeouts
- 308 agents detected
- 755 tools detected
- 84 MCP servers detected
- 1,294 ADG nodes
- 1,459 ADG edges
- 14/21 repositories with complete static coverage

The remaining incomplete application cases are primarily explicit runtime or
dynamic configuration boundaries that HorusTrace reports rather than guesses.

## Validation

v0.4.1 has been validated with:

- Python 3.11
- Python 3.12
- 279 local tests
- reviewed benchmark corpus
- package/wheel smoke testing
- HorusTrace self-scan
- CodeQL
- application and framework-stress public corpus workflows

## Compatibility

This is a patch release. Existing CLI commands, configuration filenames, rule
identifiers, and finding fingerprints remain compatible with v0.4.0.

Install with:

```bash
pip install --upgrade horustrace==0.4.1
```
